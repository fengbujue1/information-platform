## 10. 实施记录

- 将 `/jobs` 从占位页替换为实际职位列表页，复用 TASK-013 的 `getJobs`，未创建新的 HTTP Client。
- URL Query 是已生效列表状态的唯一事实来源；表单、分页、每页数量和排序只更新路由，由单一路由监听器触发请求。
- URL 解析支持全部合同参数，对页码、每页数量、非负整数薪资、排序字段和排序方向执行前端基础校验；明显非法值恢复安全默认值并显示提示。
- 空筛选条件不写入 URL，分页和排序显式保留，保证复制链接、刷新以及浏览器前进后退能够恢复状态。
- 搜索将页码重置为 1；重置清空筛选并恢复默认排序，同时保留当前 `size`；修改 `size` 后页码重置为 1。
- 请求切换时使用 `AbortController` 取消上一请求，并使用单调递增的请求序号忽略无法及时取消的旧响应。
- 请求开始时清除旧成功结果，失败时展示稳定的中文错误和重试入口，不把旧数据伪装成最新结果。
- 后端返回的总页数小于当前页时，使用 `router.replace` 回到最后一个有效页，由路由监听器只发起一次修正后的请求。
- 筛选区域在窄屏下改为单列；结果区域在桌面端使用表格，在窄屏下使用可点击卡片。
- `source`、`jobStatus` 和 `remoteType` 因合同没有冻结枚举值，按用户确认采用文本输入，不猜测封闭选项。
- 新增 `/jobs/:id` 最小占位路由，只承接列表导航和经过站内路径校验的 `from`，不调用详情 API；详情内容仍属于 TASK-015。
- 未增加 rawPayload、用户系统、写操作、Collector 修改、AI、推荐、通知或新的基础设施。
