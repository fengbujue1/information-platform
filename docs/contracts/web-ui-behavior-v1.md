# Web UI Behavior V1

状态：Accepted
接受日期：2026-07-29
适用阶段：Phase 2
依赖契约：Job Query API V1

## 1. 目的

本文件定义 Phase 2 Web MVP 的页面、路由、URL 状态和错误处理行为。

它不修改 Job Query API V1，也不新增后端写入能力。

## 2. 页面和路由

| 页面 | 路由 | 说明 |
|---|---|---|
| 职位列表 | `/jobs` | 默认入口 |
| 职位详情 | `/jobs/:id` | 展示当前职位 |
| 历史快照 | `/jobs/:id/snapshots` | 展示历史版本 |
| 404 | 任意未知路由 | 提供返回职位列表入口 |

## 3. 职位列表参数

前端 URL Query 与后端参数同名：

| 参数 | 前端默认值 |
|---|---|
| `page` | `1` |
| `size` | `20` |
| `keyword` | 空 |
| `company` | 空 |
| `city` | 空 |
| `salaryMin` | 空 |
| `salaryMax` | 空 |
| `source` | 空 |
| `jobStatus` | 空 |
| `remoteType` | 空 |
| `sortBy` | `firstSeenTime` |
| `sortDirection` | `desc` |

允许的排序字段：

- `firstSeenTime`
- `lastSeenTime`
- `publishTime`
- `salaryMinMonthlyYuan`

前端不得发送白名单之外的排序字段。

## 4. 列表状态行为

### 4.1 初次进入

- 从 URL 读取参数。
- 合法化参数。
- 发送一次列表请求。
- 不因表单组件初始化重复发送请求。

### 4.2 执行搜索

- 点击搜索后，将 `page` 重置为 1。
- 把筛选条件写入 URL。
- URL 更新触发请求。
- 空字符串参数可以从 URL 中移除。

### 4.3 重置

- 清空筛选条件。
- 恢复默认排序。
- `page=1`。
- 保留用户当前 `size`，其他参数恢复默认。

### 4.4 分页

- 页码和每页数量写入 URL。
- 修改每页数量后将页码重置为 1。
- 后端返回总页数小于当前页时，前端回到最后一个有效页，避免循环请求。

## 5. 从列表进入详情

进入详情时，将当前列表 URL 编码后写入 `from` 参数：

```text
/jobs/1001?from=<编码后的列表 URL>
```

规则：

1. `from` 只接受以 `/jobs` 开头的站内路径，禁止作为外部跳转地址。
2. 参数缺失、解码失败或校验不通过时，返回默认入口 `/jobs`。
3. Router State 可以作为交互优化，但不能作为唯一的列表状态恢复来源。
4. 刷新详情或快照页面后，返回列表行为仍必须可靠。

## 6. 详情显示规则

- 正文按纯文本展示并保留换行。
- `null` 或空字符串显示统一占位符，例如 `—`。
- 来源链接在新标签页打开。
- 来源链接必须使用 `noopener noreferrer`。
- 不渲染 rawPayload。
- 不使用 `v-html`。
- 不把内容 Hash 作为主要业务信息突出展示。

## 7. 快照显示规则

快照默认按后端返回顺序展示。

每个版本至少显示：

- versionNo
- createdAt
- collectedAt
- title
- content
- contentHash
- collectorVersion
- standardizedPayload

`standardizedPayload` 使用只读 JSON 查看器或格式化 `<pre>` 展示。

Phase 2 不要求：

- rawPayload；
- 逐字符 Diff；
- 快照修改；
- 快照删除。

## 8. 日期显示

后端返回 UTC ISO-8601。

前端：

- 使用浏览器本地时区显示；
- 在 Tooltip 或详情中保留原始 UTC 值；
- 使用统一日期格式化函数；
- 不手工给时间加固定 8 小时。

## 9. 薪资显示

优先显示 `salaryText`。

当原始文本缺失而标准薪资存在时，才使用格式化后的人民币元/月区间。

前端不自行重新解释薪资业务规则。

## 10. 错误处理

### 10.1 列表请求失败

显示：

- 错误摘要；
- 重试按钮；
- 保留当前筛选条件；
- 不把旧数据伪装成最新成功结果。

### 10.2 详情 404

显示职位不存在页面，并提供返回列表入口。

### 10.3 参数错误

- 前端先做基础校验。
- 后端仍是最终校验者。
- 后端错误码映射为可理解的中文提示。
- 不直接向用户展示 Java 堆栈或 Axios 内部对象。

### 10.4 网络断开

显示网络错误和重试入口。

## 11. 空数据

列表为空时：

- 显示“没有符合条件的职位”；
- 提供重置筛选入口；
- 不显示错误样式。

快照为空时：

- 显示“当前职位暂无历史版本”；
- 不把它视为接口失败。

## 12. Loading

- 列表使用表格或卡片 Skeleton。
- 详情使用内容 Skeleton。
- 快照加载与详情加载相互独立。
- 请求期间防止重复提交同一个搜索动作。

## 13. API 类型规则

TypeScript 类型必须来自 Job Query API V1 和后端实际响应。

禁止：

- 给响应类型增加后端不存在的字段；
- 假设 nullable 字段必然有值；
- 用 `any` 跳过类型；
- 在多个页面重复定义同一响应类型。

## 14. 安全和访问范围

- 当前 UI 不读取 rawPayload。
- 当前 UI 不保存 Collector Token。
- 当前 UI 不提供写操作。
- Identity MVP 实施前无读取认证时，不允许直接公开到公网。
- Identity MVP 实施后，访问 `/jobs`、详情和快照路由前必须确认 Session；未登录跳转 Login，并在登录后恢复原站内路径。
- Axios 同源请求携带 Session Cookie；状态修改请求携带服务端 CSRF token。
- 401 清理前端认证态并进入登录流程；403 不得误报为网络错误。
- 现有 Job 页面仍不得读取 rawPayload 或保存任何服务器秘密。
