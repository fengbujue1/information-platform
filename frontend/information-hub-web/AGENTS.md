# Information Hub Web 开发规则

## 一、模块定位

本模块是 Information Platform 的信息浏览和管理前端。

负责：

- 信息列表；
- 职位列表；
- 信息详情；
- 搜索和筛选；
- AI 分析结果展示；
- 推荐结果展示；
- 采集器和任务状态展示。

前端不得直接访问 MySQL，也不得直接调用采集器。

所有业务数据通过 Information Hub REST API 获取。

## 二、技术栈

- Vue 3
- TypeScript
- Vite
- Element Plus
- Pinia
- Axios

除非当前 TASK 明确要求，不引入另一套 UI 框架或状态管理框架。

## 三、目录建议

src/
├── api/
├── components/
├── views/
├── router/
├── stores/
├── types/
├── utils/
└── layouts/

职责：

api/：HTTP 请求封装；
types/：后端协议类型；
views/：页面；
components/：可复用组件；
stores/：跨页面状态；
utils/：纯工具函数。
##四、业务边界

前端可以：

展示后端字段；
组合查询参数；
管理页面状态；
格式化时间和显示文本。

前端不得：

自己重新计算正式推荐分；
根据 JD 擅自判断远程类型；
在浏览器中调用大模型；
将后端业务校验只实现于前端；
保存数据库密码或 AI Key。

正式业务结果以后端为准。

##五、API 规则
所有请求集中放在 src/api/。
页面组件中不直接创建 Axios 实例。
请求和响应必须有 TypeScript 类型。
错误处理应统一封装。
不使用 any 逃避类型定义，除非有明确注释。
原始 payload 展示需要处理超长内容。
后端字段发生变化时同步更新协议类型。
##六、组件规则
页面组件不要堆积所有 UI 和数据逻辑。
通用筛选器、分页器、JSON 查看器应提取组件。
组件 Props 和 Emits 必须声明类型。
不在模板中写复杂计算。
不随意使用全局状态。
列表筛选状态是否持久化，应由当前 TASK 决定。
